# Note evidence protocol

The experimental fixed vocal recipe retains model observations independently of edits. `GET /api/songs/{song_id}/notes` returns `score_sha256`, `evidence_generation` and the revision of the same score snapshot as its notes. To inspect a note from that response, call `GET /api/songs/{song_id}/notes/{note_id}/evidence` with `expected_revision`, `expected_score_sha256`, and `expected_generation`. A mismatch returns 409. All three are needed: layout and Undo can reuse a revision and identical bytes can occur on different edit branches. Evidence GET reads the current database snapshot and does not run Song reconciliation.

A schema v1 `linked` response identifies one selected performed MIDI event using `selected-midi-v1:<sha256>:<midi_notes index>`, its performed seconds, interpreted grid seconds, written quarter positions, and every current locator in its tie chain. This layer contains the selected performed MIDI. `unavailable` means the evidence or proof is missing or unsupported. `ambiguous` means multiple written chains match. A source-audio seek is returned only when the owned WAV, source and model hashes, untrimmed context, playback duration and applicable beat receipt validate. This position is an interpreted grid candidate. Unsupported or inconsistent sources return null.

For example, an owned synthetic score with one note tied across two bars may return `locators: ["p0-m0-n0", "p0-m1-n0"]`. These positional locators apply only to the returned score snapshot.

A newly ingested fixed-recipe Song receives an active baseline only after its retained evidence and original written score validate together. Existing Songs without that admission remain unavailable; matching content alone cannot establish identity. The first publication layout can retain an active baseline when its notes and clock remain unchanged. Other score or revision writes invalidate the active lineage by default, including Undo and untracked edits. The desktop includes the revision, hash and generation from `/notes` in its sparse structure PATCH. Existing clients may omit them, but a supplied stale precondition returns 409. For a proven untied pitch-only edit with revision and hash preconditions, the score and an append-only patch edge commit in the same SQLite transaction and activate its successor lineage. An edge records both revisions and XML hashes, the locator, before/after pitch and spelling, source IDs, and manual-edit reason. Undo retains old edges without reactivating them.

## Manual rhythm edits

`POST /api/songs/{song_id}/notes/rhythm-edit` requires the revision, XML hash and generation from `/notes`. Send `action` and the current `note_ids` in score order. A `split` divides one untied pitched note into two attacks, `merge` combines two adjacent notes of the same written pitch, `boundary` redistributes time between two adjacent notes or rests, and `delete` replaces one pitched note with a rest of the same duration. Supply `left_note_type` and optional `left_dots` for split and boundary. The two durations must add up exactly to the selected region.

This path supports a linear voice within one measure. An unsafe operation returns 422, including edits that would move a tempo or harmony marker or lose notation attached to a target. Stale tokens return 409. The response gives the new affected locators and the pitch, source IDs and written quarter interval of each input and output.

An active Song stores a versioned successor map and an append-only edit in the same transaction as the MusicXML. The map follows surviving XML elements through positional index changes. Split children share their parent source ID, a merge of two linked notes carries both parents' proven source IDs, and a deleted attack stays in the patch input. If either merged parent has no proven link, the merged output remains unavailable; the patch inputs still retain any known source IDs. Legacy Songs save supported written edits and their history with empty source lists. A later pitch edit carries forward the active map. Undo invalidates the active map and retains the history.

Evidence schema v2 exposes the current `written_quarters`, `locators`, `source_ids` and the original `sources`. Each source retains its own performed MIDI seconds, interpreted grid seconds and verified grid seek. A single source also appears in the usual top-level fields. Split children inherit the same source seek while their current written boundaries differ. A merge has null singular fields. Clients can inspect and audition its sources individually. Malformed or unsupported lineage returns an unavailable result.

### Optional raw vocal hypotheses, version 1

Fresh fixed-vocal runs may declare `vocal_hypotheses` in the caller's recipe. The private, immutable `vocal/note-hypotheses.json` binds the stem observed before and after both model calls to the Tiny receipt, raw YourMT3 MIDI and runtime, selected MIDI, and Tiny archive and runtime hashes. The caller makes this binding; the historical YourMT3 runtime receipt did not identify its input or output. Older jobs therefore have no such prefix, even if their bytes happen to match another run. A declared missing, unsafe, corrupt or oversized sidecar prevents initial evidence preservation and Job cleanup. A bounded or unsupported event stream can instead declare the prefix unavailable while the score remains usable.

Raw IDs identify decoder output events, including original MIDI track, channel and program. Matching requires a unique pitch, instrument/percussion identity, and exactly equal tempo-integrated MIDI tick start and release. This is unique performed-event equivalence, not proof of causal ancestry; duplicate candidates or competing selected events are ambiguous. The decoder's start and release are model segment candidates in its input clock, not measured acoustic or perceptual boundaries. An unavailable or ambiguous match never changes a note.

The independently versioned `vocal_hypotheses` API field is advisory and is evaluated only after the existing selected-note baseline and edit lineage. It contains per-source status, counts, linked model segments and half-open frame index bounds; it never returns raw arrays. Tiny frames are co-temporal in the **stem-local** clock at 0.01-second intervals. The retained v2 archive contains raw pitch, periodicity and A-weighted loudness as well as filtered pitch and times; periodicity is not a calibrated voicing probability. A range can be empty and is not an onset or offset measurement. Legacy, unsupported, malformed or unproven prefixes are unavailable; unknown is not zero or false. Split and merge carry the observations of their proven sources, and unproven ancestry abstains. Existing source-audio seek remains based solely on the previously verified grid, not the stem clock.

The prefix is model provenance, not independent ground truth, a claim of musical accuracy, or completion of the broader acoustic/perceptual hypothesis graph. Raw candidates and frame arrays remain private retained evidence; the public field is bounded and contains no audio or raw arrays.

### Opt-in continuous pitch view

The authenticated desktop may add `include_pitch_observations=true` to the same guarded note-evidence request. Only this explicit request returns an independently versioned `pitch_observations` view. The default response remains metadata-only. This view reads retained Tiny v2 observations; it neither runs a model nor changes the archive, score, recipe, lineage, or audio seek. The response also identifies the evidence generation used for the snapshot.

An available version-1 view uses `frame_clock: "stem_local"`, `algorithm: "tiny-frame-window-v1"`, and the verified pitch, stem, and pitch-runtime hashes. Each source is identified by its existing selected-MIDI source ID. Its original half-open frame interval is padded by up to 25 frames on each side, bounded by the retained archive. At most 16 sources and 1,201 frames per padded window are returned. Empty or oversized intervals abstain explicitly; frames are never silently truncated or downsampled. A split therefore shows the parent's original observation interval for both children; a merge keeps each parent's observations separate.

Each frame contains its retained index, time in seconds, `raw_hz`, filtered `hz`, `periodicity`, and `loudness_db_a`. The existing filter is unchanged: periodicity at least 0.21 and A-weighted loudness at least −60 dB are required to retain a pitch, with comparisons performed in the original array dtype. The desktop uses the retained filtered value rather than recomputing that decision in JavaScript float64: a float32 value displayed as `0.20999999344348907` can pass the original float32 comparison. Filtered zero means rejection by that model's conditions. It does not establish silence, absence of vocals, or a notated rest. Periodicity is not a calibrated probability. Separate accepted/rejected observations and the current written pitch are shown in the desktop; the graph does not automatically correct either pitch or rhythm.

`gate_transitions` mark adjacent retained frame centers at which the acceptance condition changes. Their brackets describe the observation grid, not confidence intervals or measurements of physical attacks/releases. Acoustic and perceptual onsets remain explicitly `not_measured`. Model performed time, stem-local frame time, interpreted grid time, and written quarter positions retain their separate meanings. In particular, the graph never substitutes its stem-local times for the independently verified original-audio seek.

A unique raw-decoder event match is not required to display co-temporal Tiny frames when the selected source and its input binding are already proven. Raw-event ambiguity stays ambiguous. An unavailable selected baseline, unsupported prefix, missing source, unsafe or changed archive, unknown version, or exceeded bound instead produces an unavailable optional view while retaining the existing baseline response. The frame bytes and receipt are validated against their retained hashes before and after reading. Legacy jobs are not backfilled with invented observations.

Frame data are private local inspection material. Public research receipts contain only aggregate counts and hashes; commercial recordings, individual musical traces, and reference annotations are not added to the repository. This inspection surface does not establish musical accuracy, complete the broader boundary/perceptual annotation schema, or replace independent reference and human correction-cost acceptance.

### Boundary and score review gates

These gates define separate review decisions. Passing one never establishes the result of another.

| Decision | Required evidence and pass meaning | Failure or deferral |
| --- | --- | --- |
| Acoustic observations and boundary candidates | Bind the original recording or continuous observations to their source, extractor, model/runtime, hashes, clock, and declared uncertainty. Check accents without new attacks, legato, slides, unvoiced intervals, and missed detections separately. Passing integrity checks establishes the identity and meaning of observations, not a correct musical onset. | A rejected frame is not proof of silence or a rest. If the available signal cannot establish a physical boundary, keep it unresolved; a decoder segment or gate transition cannot certify it. |
| Perceptual onset | Independent listeners mark heard onsets or uncertainty intervals from the exact original recording with model and score-grid positions hidden. Preserve disagreements and any adjudication. Only this listening evidence can support a perceptual-onset decision. | Missing listening annotations or unresolved disagreement defer the decision. A pitch curve, waveform peak, or matching grid position cannot substitute for blinded listening. |
| Performed timing and written rhythm | Compare performed events with independent timed note annotations, and common written rhythm with a separately aligned written reference. Evaluate pitch, attacks/releases, rests, ties, pickup, meter/tempo changes, and applicable voice/instrument identity in their own layers. Verify timing and original-evidence preservation across edits separately from notation recovery. | Model-to-export fidelity proves conversion preservation, not original-song correctness. Missing or ambiguously aligned references defer musical approval. Do not choose alignment, octave folding, or a favorable excerpt after seeing scores and present it as independent whole-song accuracy. |
| Human correction and publication | Start from the same declared score revision and recording. Observe actual correction actions, time to publish, residual errors, export success, and failures. Agree on acceptable musical errors and correction burden before the final acceptance comparison. | Automated edits and edit-count proxies are not measured human effort. Missing independent references, observations of editing, or agreed limits keep product acceptance pending. |

The five requested recordings are an acceptance/development corpus already used for inspection; they are not an unseen holdout. Independent whole-song references, blinded listening annotations, and the user's acceptable correction burden are still pending. This section defines the checks; it does not report those checks as completed or approve a model, boundary algorithm, or publication quality.
