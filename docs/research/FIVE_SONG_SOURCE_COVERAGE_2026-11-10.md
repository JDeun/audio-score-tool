# Full-source coverage failure and preprocessing fix

고정 `vocal_lead_v1`의 실제 업로드→모델 추론→Song→PDF/MIDI/MusicXML 실행은 5곡 모두 파일을 생성했다. 그러나 source commit `94653bbbac867d341dfc8db91278a936edbaadcd`의 공통 전처리가 원음 앞부분을 잘라내 **전곡 채보 인수에는 5곡 모두 실패**했다. 파일 export 성공이나 격자→MIDI 보존 검사가 원곡 전체를 다뤘다는 검사는 아니었다. 최초 실행·PDF·원음·raw 예측은 비공개 작업 공간에 유지하고, 원래 실행 receipt를 덮어쓰지 않은 별도 실패 기록을 추가했다.

| 곡 | 원음 길이 | 잘라낸 앞부분 | 에너지 감지 점수 |
|---|---:|---:|---:|
| Me So Bad | 210.517s | 72.400s | 0.841 |
| FANCY | 218.639s | 170.295s | 0.844 |
| American Idiot | 174.320s | 28.839s | 0.880 |
| 나의 노래 | 309.731s | 101.076s | 0.844 |
| 사건의 지평선 | 300.787s | 73.073s | 0.870 |

`estimate_music_start`는 에너지·spectral-flux가 크게 바뀌는 위치를 찾는다. 이 값은 **앞부분이 비음악이라는 판정이나 보정된 확률이 아니다.** `confidence>=0.72`와 시작 시각 조건만으로 FFmpeg `-ss`를 적용하던 공유 `prepare_music_audio`가 조용한 구간·절·보컬까지 삭제했다. 모델이 받은 입력부터 짧아졌으므로, 최종 출력이 그 입력을 충실히 보존해도 원곡의 앞부분은 복원할 수 없다.

수정은 감지 결과를 관측 후보로 보존하고 **원래 입력 전체를 모델에 전달**하는 것이다. 감지 점수를 높이거나 곡별 예외를 추가하지 않았다. 기존에 실제 crop이 적용된 Song의 시간축을 해석하는 `trimmed` 필드는 유지하되, 새 자동 전처리에서는 감지 결과만으로 이를 적용하지 않는다.

실제 동일 5곡을 FFmpeg 분석 경로로 다시 통과시켜 **반환된 모델 입력의 SHA256이 원음과 5/5 동일하고 적용 crop은 모두 0초**임을 확인했다. 후보 시각과 heuristic 점수는 그대로 남아 있다. 조용한 음악이 처음부터 있는 합성 입력에 잘못된 고신뢰 시작 후보를 공급해도 trim 명령을 실행하지 않는 회귀를 추가했다. [원음 hash·실측 metadata](FIVE_SONG_SOURCE_COVERAGE_2026-11-10.json).

이 검사는 수정된 **입력 보존 계약**의 검증이다. 수정 후 모델의 5곡 전곡 재추론·최종 export·원음 대조 및 실제 수정량 검증은 다시 실행해야 한다. 모델 정확도, 자연스러운 리듬 표기, 전주 악기의 보컬 오인과 최소 수정 출판 품질을 완료로 처리하지 않는다. 이전 연구용 전체 음원 실험과 잘린 제품 입력 실험을 같은 결과로 합산하지 않는다.
