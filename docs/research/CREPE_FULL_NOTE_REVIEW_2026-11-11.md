# TorchCREPE full 음표 검수 연구 — 2026-11-11

Vocadito 40곡에서 기존 tiny와 full의 파형 기반 음표 검수 결과를 같은 설정으로 비교했다. 두 모델의 차이는 작았으며, 한 곡 CPU 비용 측정에서 full은 tiny보다 느렸다. Full의 최대 RSS만 측정됐으므로 메모리 사용량의 우열은 판단하지 않는다. 이 결과에 따른 검수 개발 기준과 전체 제품 품질 승인은 구분한다.

## 음표 검수

원래 A1/A2 사람 주석의 Hz를 가장 가까운 반음으로 변환해 악보 대리 음표를 만들었다. 이 대리 음표는 검수기의 calibration에만 사용했으며 예측 입력으로 사용하지 않았다. 비교는 고정 설정의 안정된 음표 내부 구간만 대상으로 했다.

재현성 정정: 이전 tiny/full 음표 검수와 tiny 5곡 스크립트는 `prepare()`를 직접 호출해 Torch seed만 0으로 설정했고, decoder의 SciPy triangular dither가 사용하는 NumPy RNG는 고정하지 않았다. 아래 수치는 보존된 해당 실행의 관측값이며, 전역 seed 0의 결정론적 반복 결과라고 주장하지 않는다. 가중치·입력·결과 SHA는 그대로 유효하다. 별도 공식 CPU 7후보 실행의 `run()`과 아래 단일 곡 비용 측정은 NumPy seed도 설정했으므로 이 정정의 대상이 아니다. 새 제품 CLI는 매 프로세스의 Python/NumPy/Torch seed를 모두 0으로 설정하며 별도 40곡 검증 중이다.

| 항목 | Tiny | Full |
|---|---:|---:|
| 대리 음표 전체 | 4,113 | 4,113 |
| 관측 가능한 음표 | 2,935 (71.36%) | 2,937 (71.41%) |
| 보류 | 1,178 (28.64%) | 1,176 (28.59%) |
| 관측 음표 중 전체 오경고 | 233 (7.94%) | 226 (7.69%) |
| 관측 음표 중 옥타브 오경고 | 5 (0.17%) | 3 (0.10%) |
| +12반음 주입 시 옥타브 검출 | 2,702/2,935 (92.06%) | 2,711/2,937 (92.31%) |

같은 캐시로 −12반음을 별도 주입했을 때 옥타브 검출은 tiny 2,707/2,935 (92.23%), full 2,714/2,937 (92.41%)였다. 양방향은 각각 독립적으로 계산했다. 원래 YourMT3 선택 음표 1,809개 중 tiny는 1,197개, full은 1,202개를 관측했다. 이 경고 수를 실제 전사 오류율로 해석하지 않는다.

원래 주석 대리 음표에서 연속 두 음의 차이가 정확히 ±12반음인 경우만 별도로 살펴보면, A1/A2 합산 5쌍과 중복 제거된 10개 끝점이었다. Tiny는 끝점 6개를 관측하고 4개를 보류했고, full은 5개를 관측하고 5개를 보류했다. 두 모델 모두 관측된 끝점에서 옥타브 오경고는 0개, 다른 pitch 오경고는 1개였다. 양 끝점이 모두 관측된 쌍은 각각 2쌍이었다. 아래 고정 규칙이 원래 부호 있는 음정을 바꾼 쌍은 tiny 1쌍, full 0쌍이었다. 이 표본은 매우 작으며 주석자가 따로 기여한 쌍을 포함한다.

## 고정 pitch 제안의 사후 비교

안정 관측 pitch와 원래 음표 차이가 0.75반음 이상이고, 관측 중앙값이 가장 가까운 정수 반음에서 0.35반음 이내일 때만 해당 pitch를 제안하는 단일 규칙을 고정했다. 시간과 음표 수는 바꾸지 않았다. 기존 원본 대비 제안의 macro F1은 다음과 같다.

| 주석 | 지표 | 원본 | Tiny 제안 | Full 제안 |
|---|---|---:|---:|---:|
| A1 | onset | 0.4957 | 0.5217 | 0.5214 |
| A1 | onset+offset | 0.2711 | 0.2839 | 0.2845 |
| A2 | onset | 0.5907 | 0.6215 | 0.6227 |
| A2 | onset+offset | 0.3463 | 0.3621 | 0.3620 |

Full은 원본 1,809음 중 82음을 제안했다. 예측 음표 길이의 60% 이상을 덮는 유일한 최대 겹침 주석이 있는 경우만 라벨링하면, A1과 A2 각각 틀린 pitch를 맞게 바꾼 경우 55개, 맞는 pitch를 틀리게 바꾼 경우 3개였다. 각각 23개와 20개는 겹침 부족으로 분류하지 못했고 모호한 최대 겹침은 없었다. 주석자 결과는 별도 집계이므로 합쳐서 독립 음표 수로 해석하지 않는다. 정확한 대리 음표에 같은 규칙을 적용했을 때 잘못 바뀐 음은 A1 15개, A2 16개였다.

## 단일 곡 CPU 비용

동일한 Vocadito 원본 한 곡(33.21초)을 tiny 다음 full 순서로 각각 새로운 CPU 프로세스에서 한 번 실행했다. 설정은 두 CPU 스레드, seed 0, 55–880Hz, 10ms hop, Viterbi, periodicity 0.21, silence −60dB였다. 시간에는 Python과 라이브러리 import, 가중치 로드, 음원 디코딩, 추론, 입력 해시 및 비공개 결과 저장이 포함된다.

| 모델 | 벽시계 시간 | 실시간 배수 | 최대 RSS |
|---|---:|---:|---:|
| Tiny | 14.16초 | 0.43× | 측정 불가 |
| Full | 117.86초 | 3.55× | 5,195,513,856 bytes (약 4.84 GiB) |

Tiny의 최대 RSS는 운영체제의 `time -l` 통계 조회가 sandbox에서 거부되어 확보하지 못했다. 반복 측정은 하지 않았다. Full의 RSS는 macOS 프로세스 `getrusage` 값이다. 실행은 순차적이었으나 파일 시스템 캐시 상태를 통제하지 않았고, 단일 실행이므로 이 수치를 40곡 전체 벤치마크나 안정적인 속도 순위로 일반화하지 않는다.

모델 코드는 torchcrepe 0.0.24, 가중치 revision `19e2ec3d494c0797a5ff2a11408ec5838fba6681`이며, 가중치와 런타임의 식별 정보는 함께 제공되는 JSON에 기록했다. 선택 음표 경고는 사람 정답이 아니며, 사용자의 실제 다섯 곡에 대한 전문가 정답도 없다. 원곡 정확도, 자동 교정 및 전체 제품 모델 조합의 최종 승인은 별도 검증이 필요하다.

## 검수 개발 기준

검수 모델 개발은 **torchcrepe tiny 한 설정으로 고정**한다. Full의 대리 음표 관측률 증가 약 0.05%p와 오경고 감소 약 0.24%p, 고정 pitch 제안의 혼재된 A1/A2 결과에 비해 단일 곡 측정에서는 약 8.3배의 시간이 들었다. 이 판단은 전체 곡의 성능 우열이나 모든 환경의 속도 순위를 주장하지 않는다. Tiny의 정확한 모델·가중치·설정은 JSON의 `development_selection`에 고정하며 full을 추가 사용자 선택지로 배선하지 않는다.

작은 검수 차이에 통계적 유의성을 주장하지 않으며, 미고정 dither의 변동을 포함한 관측값만으로 모델의 정확도 우열을 확정하지 않는다.

이는 새로운 검수 runtime을 연결하고 검증할 개발 기준이다. 현재 제품의 YIN 검수 경로가 이미 tiny로 교체됐다는 뜻은 아니며, 제품 배선과 실제 5곡 검증은 후속 작업이다. 자동 pitch 수정은 대리 정답 음표와 실제 도약을 손상한 사례가 있어 계속 미승인이다. 전체 모델 조합·최소 수정·상용 품질도 미승인 상태로 유지한다.
